# HushWake 0.3.3-beta 实体机测试指南

本指南用于当前智能输出测试版的实机验收。普通外放是预期功能；只有在界面显示耳机播放或已检测到耳机时仍从扬声器出声，才属于必须立即停止测试的串音问题。

## 测试前准备

- Android 12 / API 31 或更高版本的实体手机。
- 一副有线耳机、蓝牙 A2DP 耳机、USB 耳机或蓝牙 LE 耳机；测试时只连接一个候选音频设备。
- 第一次测试在允许短暂声音外放的私人环境中进行，不要直接在办公室、宿舍夜间或安静车厢试验。
- 将系统媒体音量手动调到较低但非 0；应用不会自动修改系统音量。

## 安装

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。开启手机的 USB 调试后，可在仓库根目录安装：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

也可以把 APK 复制到手机后手动安装。包名是 `com.hushwake.app`，应用名是“悄醒”。

`0.3.3-beta` 可覆盖安装并保留闹钟数据。Android 13+ 的全新安装会直接具备闹钟应用所需的精确调度能力；Android 12 如果显示授权提示，请按页面入口允许。升级后若已确认过智能输出原则，不会重复展示首次确认页。

## 用例 0：智能外放

1. 确保没有连接有线、USB 或蓝牙耳机，并保留蓝牙连接权限。
2. 启动助眠声，确认界面显示“扬声器播放 · 当前无耳机”，手机扬声器有声。
3. 创建 1 分钟测试闹钟，确认到点从系统媒体输出正常响铃。
4. 将媒体音量调到 0，确认应用不自动调高音量。

预期：无耳机时闹钟和助眠声均可正常外放，不要求完成耳机隐私测试。

## 用例 A：正常路由

1. 连接唯一一副待测耳机，打开应用并确认“候选输出”类型正确。
2. 确认验证等级：API 36+ 应显示“强验证”，API 31–35 应显示“兼容验证”。
3. 勾选“当前唯一候选设备是仅本人佩戴的耳机”，开始 10 秒测试。
4. 观察安全链路依次出现静音、实际路由验证和低增益渐强；确认手机扬声器全程无声。
5. 测试结束后按真实听感选择“是，只在耳机”或“外放或不确定”。

预期：只有耳机播放低音量测试音；本地报告记录验证等级与粗粒度输出类型。API 31–35 的通过结果仍只是兼容证据，不等于系统证明没有并行输出。

Android 可能在正常 A2DP 起播时发出路由回调。应用应先短暂静音并重新验证；候选和实际路由仍是同一副安全耳机时继续测试，不得立即显示“目标耳机已断开”。

人工确认通过后，记录只绑定当前这一副耳机：有效期 90 天；Android 大版本或应用音频引擎升级、耳机变化后自动失效。无法生成稳定本机哈希的耳机不能开放正式声音。

## 用例 B：有声期间断连

1. 重新开始测试，等界面进入“仅耳机测试中”。
2. 在测试音播放期间拔出有线/USB 耳机，或关闭蓝牙耳机。
3. 观察界面是否立即进入“声音已阻断”，并检查耳机断开后手机扬声器是否完全无声。
4. 复制“本地诊断”摘要，保留其中的阻断原因和检测到静音延迟。

预期：应用先把自身增益归零，再停止播放器；不得从扬声器继续播放测试音。

## 用例 C：不合格环境

隐私测试实验室分别验证以下状态：无耳机、媒体音量为 0、同时存在多个候选个人输出。预期实验室测试按钮不可用或启动后立即阻断；正式闹钟和助眠声在无耳机时则按用例 0 正常外放。媒体音量为 0 时应用不自动调高，多耳机目标不唯一时正式声音仍阻断。

## 用例 D：正式闹钟

1. 允许通知、全屏闹钟入口和蓝牙连接能力；Android 12 若出现精确闹钟提示，也从页面入口允许。若首页显示“后台运行已受限”，从“去解除”进入应用详情，将电池用量设为“不受限制”，并按本机系统允许自启动；即使没有警告，也可从已启用闹钟的“点此检查电池/自启动”进入检查厂商开关。
2. 使用小时/分钟滚轮和“15 分钟后”等快捷项各设置一次，确认编辑页没有启停开关，保存后的时间准确且列表开关自动开启。
3. 分别在无耳机和已完成当前耳机隐私测试两种环境创建 1 分钟测试闹钟。
4. 在编辑页横向浏览六种 AOSP 专业闹铃素材，逐项点选并确认立即试听；再点当前铃声也会重播，有耳机时试听同样不得外放。
5. 按 Home 返回桌面并从最近任务划走应用，再熄屏等待到点；不要使用系统“强行停止/强制停止”，该操作会由 Android 阻断后续事件且任何应用内权限都不能绕过。确认无耳机时正常外放，有耳机时声音只在耳机中。
6. 连续观察至少 20 秒，确认响铃在渐强后持续循环而不是只响一遍；再分别验证停止、一次稍后提醒、最长响铃自动结束和一次性闹钟自动停用。
7. 创建周重复闹钟，重启设备和修改时区后确认下一次计划已重新计算；不得补播已经过去的实例。
8. 重复闹钟响铃时回到主页关闭对应开关，确认声音和振动立即停止；一次性闹钟响铃时点击卡片上的“正在响铃 · 立即停止”，确认同样立即停止，并确认服务停止后该按钮立即从卡片消失。

预期：保存成功与有声就绪分别显示。全屏入口不可用时退化为高优先级通知，不绕过系统设置；有耳机时由耳机验证条件决定，无耳机时使用系统媒体外放。

## 用例 E：助眠声

1. 分别在无耳机和当前已验证耳机环境浏览六种真实环境录音，抽测系统媒体音量键、暂停/继续和通知控制。
2. 播放期间依次点“夜雨”“溪流”“壁炉”，确认声音立即切换，不需要先停止；倒计时不得因换声重置。暂停后换声应保持暂停，继续时播放新选择。
3. 验证 15/30/45/60 分钟定时与 0/5/15/30 秒渐隐；暂停期间定时器继续。
4. 播放中断开耳机，确认应用先静音、停止且扬声器无声。
5. 助眠声播放中触发闹钟，确认助眠声先结束再建立独立闹钟会话。

预期：无耳机时助眠声正常外放；耳机播放中不得跟随系统切到扬声器；播放卡片内的暂停与停止相邻；播放中只出现一处实时剩余时间；“持续播放”仍有 8 小时硬上限。

## 用例 F：播放中接入耳机

1. 无耳机启动助眠声，确认正在外放。
2. 连接一副已通过隐私测试的耳机。
3. 确认应用立即静音外放，随后仅在耳机中恢复渐强。
4. 换成一副未通过隐私测试的耳机重复，确认外放停止且会话被阻断。

预期：耳机接入后不存在扬声器与耳机并行有声窗口；不会为了继续播放而绕过耳机验证。

## 反馈内容

请复制 App 内诊断摘要，并补充：手机 Android 版本、耳机大类（有线/蓝牙 A2DP/USB/蓝牙 LE）、是否出现任何扬声器声音。无需提供蓝牙名称、地址或精确作息时间。

若出现扬声器误播，请停止继续测试，不要尝试通过放宽检查绕过阻断，并把复现步骤与诊断摘要发回开发任务。
