# HushWake 0.4.7-beta 实体机测试指南

本指南用于当前智能输出测试版的实机验收。普通外放是预期功能；只有在界面显示耳机播放或已检测到耳机时仍从扬声器出声，才属于必须立即停止测试的串音问题。

## 测试前准备

- Android 12 / API 31 或更高版本的实体手机。
- 一副有线耳机、蓝牙 A2DP 耳机、USB 耳机或蓝牙 LE 耳机；测试时只连接一个候选音频设备。
- 第一次测试在允许短暂声音外放的私人环境中进行，不要直接在办公室、宿舍夜间或安静车厢试验。
- 将系统媒体音量手动调到较低但非 0；应用不会自动修改系统音量。

## 安装

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。开启手机的 USB 调试后，可在仓库根目录安装：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

也可以把 APK 复制到手机后手动安装。包名是 `com.hushwake.app`，应用名是“悄醒”。

`0.4.7-beta` 可覆盖安装并保留闹钟数据。Android 13+ 的全新安装会直接具备闹钟应用所需的精确调度能力；Android 12 如果显示授权提示，请按页面入口允许。升级后若已确认过智能输出原则，不会重复展示首次确认页。安装后在桌面检查图标：内层米色 B1-A 标识四周应有清晰深色留白，在圆形或圆角矩形遮罩下均不得贴边或被裁切。

## 用例 0：智能外放

1. 确保没有连接有线、USB 或蓝牙耳机，并保留蓝牙连接权限。
2. 启动助眠声，确认界面显示“扬声器播放”和“内置音效引擎 · 跟随系统音量”，手机扬声器有声。
3. 创建 1 分钟测试闹钟，确认到点从系统媒体输出正常响铃。
4. 将媒体音量调到 0，确认应用不自动调高音量。

预期：无耳机时闹钟和助眠声均可正常外放。

## 用例 A：正常路由

1. 连接唯一一副待测耳机，打开应用并确认顶部自动切换为“耳机播放”，且没有“确认耳机”按钮或 10 秒验证页面。
2. 启动助眠声，确认播放器先以静音增益建立路由，再只在耳机中渐强；手机扬声器全程无声。
3. 停止后重新播放，并在闹钟编辑页试听铃声，确认均不需要人工确认且仍只在耳机中有声。
4. API 36+ 应以全部实际路由作为强证据；API 31–35 使用当前单路由兼容证据，实体机验收结论仍不得描述为系统级绝对保证。

预期：页面仅展示当前媒体输出状态；每次播放自动验证本次播放器实际路由，路由通过才解除静音，不保存耳机名称、地址、哈希或人工验证记录。

Android 可能在正常 A2DP 起播时发出路由回调。应用应先短暂静音并重新验证；候选和实际路由仍是同一副耳机时继续播放，不得立即显示“目标耳机已断开”。

## 用例 B：有声期间断连

1. 以唯一耳机启动助眠声或 1 分钟测试闹钟，等声音只在耳机中播放。
2. 在播放期间拔出有线/USB 耳机，或关闭蓝牙耳机。
3. 观察播放是否立即停止，并检查耳机断开后手机扬声器是否完全无声。

预期：应用先把自身增益归零，再停止播放器；不得从扬声器继续播放。

## 用例 C：不合格环境

分别验证以下状态：无耳机、媒体音量为 0、同时存在多个候选个人输出。无耳机时按用例 0 正常外放；媒体音量为 0 时应用不自动调高；多耳机目标不唯一时正式声音仍阻断。应用中不得重新出现人工耳机测试入口。

## 用例 D：正式闹钟

1. 允许通知、全屏闹钟入口和蓝牙连接能力；Android 12 若出现精确闹钟提示，也从页面入口允许。保存或从列表重新启用闹钟后不得自动弹出权限对话框或打开系统设置；缺项应留在列表顶部的内联卡片。共享顶部输出卡不得再显示“音量调节”；自启动未确认时显示琥珀色“自启动待确认”，确认后切换为薄荷色“自启动已确认”，两种胶囊都应有按压反馈且可进入设置。闹钟编辑页未确认时继续提示风险，闹钟卡片不重复显示启动检测提醒。用户可随时从顶部重新进入厂商启动管理页；每次返回后都应弹出确认框，选择“还没开启”应立即恢复待确认状态，选择“已经开启”后入口也不得消失。确认框应提示“若需关闭应用后也正常唤起闹铃，请开启‘自启动’、‘允许后台启动’权限”。
2. 创建两条不同时间的已开启闹钟，确认最近一条只出现在“下一次响铃”焦点卡，另一条出现在“其他闹钟”，两处不重复。点击焦点卡应进入对应编辑页；关闭焦点卡开关后，下一条已开启闹钟应立即提升为新焦点，原闹钟移到“其他闹钟”并显示已关闭。再使用小时/分钟滚轮和“15 分钟后”等快捷项各设置一次，确认编辑页没有启停开关，保存后的时间准确且列表开关自动开启。
3. 分别在无耳机和唯一耳机已连接两种环境创建 1 分钟测试闹钟。
4. 在编辑页横向浏览六种 AOSP 专业闹铃素材，逐项点选并确认立即试听；再点当前铃声也会重播，有耳机时试听同样不得外放。
5. 按 Home 返回桌面并从最近任务划走应用，再熄屏等待到点；不要使用系统“强行停止/强制停止”，该操作会由 Android 阻断后续事件且任何应用内权限都不能绕过。确认无耳机时正常外放，有耳机时声音只在耳机中。
6. 连续观察至少 20 秒，确认响铃在渐强后持续循环而不是只响一遍；点击“稍后 5 分钟”时按钮应立即显示正在设置，响铃停止后给出新时间反馈，同一闹钟卡片应改为该时间并开启，重复闹钟保留原星期选择。重新打开应用后目标时间不得漂移。再分别验证停止、最长响铃自动结束和一次性闹钟最终停用。
7. 创建周重复闹钟，重启设备和修改时区后确认下一次计划已重新计算；不得补播已经过去的实例。
8. 闹钟响铃时回到主页，确认该闹钟仍占据“下一次响铃”焦点卡，焦点卡显示开关与“正在响铃 · 立即停止”，“其他闹钟”不重复显示；不得出现“暂无已开启闹钟”。关闭焦点开关或点击立即停止，确认声音和振动立即停止；服务确认停止后，下一条已开启闹钟应自动成为焦点，没有下一条时才显示空状态。

预期：保存成功与有声就绪分别显示。全屏入口不可用时退化为高优先级通知，不绕过系统设置；有耳机时由本次实际路由条件决定，无耳机时使用系统媒体外放。

## 用例 E：助眠声

1. 分别在无耳机和唯一耳机环境浏览八种真实环境录音；确认每张卡片具有对应环境底纹，海浪和远雷可正常解码播放，再抽测系统媒体音量键、暂停/继续和通知控制。
2. 播放期间依次点“夜雨”“溪流”“壁炉”，确认声音立即切换，不需要先停止；倒计时不得因换声重置。暂停后换声应保持暂停，继续时播放新选择。
3. 验证滑杆可按 5 分钟步长选择 5–120 分钟，并验证 0/15/30 秒三档结束方式；暂停期间定时器继续。
4. 播放中断开耳机，确认应用先静音、停止且扬声器无声。
5. 助眠声播放中触发闹钟，确认助眠声先结束再建立独立闹钟会话。

预期：无耳机时助眠声正常外放；耳机播放中不得跟随系统切到扬声器；播放卡片内的声波随播放状态变化，暂停与停止相邻；播放中只出现一处实时剩余时间；播放前可通过滑杆选择 5–120 分钟，并可选择 15 秒渐隐、30 秒渐隐或立即停止。

## 用例 F：播放中接入耳机

1. 无耳机启动助眠声，确认正在外放。
2. 连接唯一一副耳机。
3. 确认应用立即静音外放，随后仅在耳机中恢复渐强。
4. 再换一副耳机重复，确认无需人工验证页，外放先停止且只有实际路由确认后才在新耳机中恢复。

预期：耳机接入后不存在扬声器与耳机并行有声窗口；不会为了继续播放而绕过本次实际路由检查。

## 反馈内容

请补充：手机 Android 版本、耳机大类（有线/蓝牙 A2DP/USB/蓝牙 LE）、操作步骤、界面顶部输出状态，以及是否出现任何扬声器声音。无需提供蓝牙名称、地址或精确作息时间。

若出现扬声器误播，请停止继续测试，不要尝试通过放宽检查绕过阻断，并把复现步骤发回开发任务。
