# HushWake 0.2.0-beta 实体机测试指南

本指南用于首个正式功能测试版的实机验收。任何一次扬声器误播都应立即停止测试、停止分享该安装包并保留诊断结果。

## 测试前准备

- Android 12 / API 31 或更高版本的实体手机。
- 一副有线耳机、蓝牙 A2DP 耳机、USB 耳机或蓝牙 LE 耳机；测试时只连接一个候选音频设备。
- 第一次测试在允许短暂声音外放的私人环境中进行，不要直接在办公室、宿舍夜间或安静车厢试验。
- 将系统媒体音量手动调到较低但非 0；应用不会自动修改系统音量。

## 安装

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。开启手机的 USB 调试后，可在仓库根目录安装：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

也可以把 APK 复制到手机后手动安装。包名是 `com.hushwake.app`，应用名是“悄醒”。

`0.2.0-beta` 已在标准 API 31、34、36 模拟器通过冷启动、五页遍历和闹钟编辑回归；API 34 另通过系统精确触发和无耳机失败静音，API 36 已进入全路由强验证分支。模拟器没有真实耳机，不能替代本指南的零泄漏验证。实验版可覆盖安装，但首次仍需完成正式版引导与权限检查。

## 用例 A：正常路由

1. 连接唯一一副待测耳机，打开应用并确认“候选输出”类型正确。
2. 确认验证等级：API 36+ 应显示“强验证”，API 31–35 应显示“兼容验证”。
3. 勾选“当前唯一候选设备是仅本人佩戴的耳机”，开始 10 秒测试。
4. 观察安全链路依次出现静音、实际路由验证和低增益渐强；确认手机扬声器全程无声。
5. 测试结束后按真实听感选择“是，只在耳机”或“外放或不确定”。

预期：只有耳机播放低音量测试音；本地报告记录验证等级与粗粒度输出类型。API 31–35 的通过结果仍只是兼容证据，不等于系统证明没有并行输出。

人工确认通过后，记录只绑定当前这一副耳机：有效期 90 天；Android 大版本或应用音频引擎升级、耳机变化后自动失效。无法生成稳定本机哈希的耳机不能开放正式声音。

## 用例 B：有声期间断连

1. 重新开始测试，等界面进入“仅耳机测试中”。
2. 在测试音播放期间拔出有线/USB 耳机，或关闭蓝牙耳机。
3. 观察界面是否立即进入“声音已阻断”，并检查耳机断开后手机扬声器是否完全无声。
4. 复制“本地诊断”摘要，保留其中的阻断原因和检测到静音延迟。

预期：应用先把自身增益归零，再停止播放器；不得从扬声器继续播放测试音。

## 用例 C：不合格环境

分别验证以下状态：无耳机、媒体音量为 0、同时存在多个候选个人输出。预期测试按钮不可用或启动后立即阻断，应用不自动调高音量，也不选择扬声器降级。

## 用例 D：正式闹钟

1. 在可靠性中心逐项允许精确闹钟、通知、全屏闹钟入口和蓝牙连接能力。
2. 完成当前耳机隐私测试，再创建 1 分钟测试闹钟。
3. 熄屏并等待到点，确认锁屏处置页或高优先级通知出现，声音只在耳机中。
4. 分别验证停止、一次稍后提醒、最长响铃自动结束和一次性闹钟自动停用。
5. 创建周重复闹钟，重启设备和修改时区后确认下一次计划已重新计算；不得补播已经过去的实例。

预期：保存成功与有声就绪分别显示。全屏入口不可用时退化为高优先级通知，不绕过系统设置；声音仍只由耳机验证条件决定。

## 用例 E：白噪音

1. 对当前已验证耳机启动四种环境音，测试增益、暂停/继续和通知控制。
2. 验证 15/30/45/60 分钟定时与 0/5/15/30 秒渐隐；暂停期间定时器继续。
3. 播放中断开耳机，确认应用先静音、停止且扬声器无声。
4. 白噪音播放中触发私密闹钟，确认白噪音先结束再建立独立闹钟会话。

预期：白噪音也不得跟随系统切到扬声器；“关闭定时”仍有 8 小时硬上限。

## 反馈内容

请复制 App 内诊断摘要，并补充：手机 Android 版本、耳机大类（有线/蓝牙 A2DP/USB/蓝牙 LE）、是否出现任何扬声器声音。无需提供蓝牙名称、地址或精确作息时间。

若出现扬声器误播，请停止继续测试，不要尝试通过放宽检查绕过阻断，并把复现步骤与诊断摘要发回开发任务。
